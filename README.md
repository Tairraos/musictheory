# 姐弟厨师团 —— 乐理课 · 作词课

两个可以"动手弄响"的互动课页面，共用一套零依赖的静态站。

| 页面 | 地址 | 讲什么 |
|---|---|---|
| **乐理课** | `index.html` | 半音 → 大小调 → 七个调式 → 五声偏音 → 和弦 → 终止式 → 速度 → 拍号 → 律动（节奏型） → 曲式（布鲁斯） → 词曲咬合 → 移调 → 十三种表达维度 → 配器与专辑 → 转调 → 速查 |
| **作词课** | `lyric.html` | 判据 → 体裁 → 押韵 → 中文句式 → 英文 prosody → 意象与修辞 → 段落 → 钩子 → 八派 → 框景与人称 → 禁则 → 改词 → 专辑规划 → 自检器 |
| **乐器课** | `instrument.html` | 怎么读音域图 → 11 族 46 件乐器的音域与常用区 → 术语速查 |
| **卡片版** | `cards.html` | 上面三门课的手机卡片版：一屏一张卡，顶部切课、底部常驻钢琴，进度按课记在本地 |

不啃符号、不背公式：乐理课每一块都能点、能听、能改参数；
作词课每条判据都标了"能不能数"——能数的交给自检器，只能人读的交给朗读。

两页各有两条互链：一条在页面最顶上（`.pageswitch` 小药丸），一条在左侧目录里
（`#nav a.navswitch`，紫底描边）。目录是 `position:fixed` 的，所以**滚到任何一节都能直接换课**，
不必先滚回顶端；窄屏下目录变成顶部横滚条，同样常驻。

> 线上试玩：**https://musictheory.2025120.xyz**
> （`/` → 乐理课，`/lyric.html` → 作词课）

## 运行

工程是**零运行时依赖**的静态站，无构建、无网络请求
（声音全部由浏览器实时合成，插图与图标都是本地 PNG）。

直接双击 `index.html` 用浏览器打开即可；或起个本地服务：

```bash
npm start            # 等价于 python3 -m http.server 8000
# 打开 http://localhost:8000        → 乐理课
# 打开 http://localhost:8000/lyric.html → 作词课
```

建议用桌面端 Chrome / Edge / Safari，手机竖屏同样适配（乐理课底部有常驻钢琴）。

## 分界：什么算乐理，什么算作词

最初那批作词资料里只有约三成是真乐理——能写成「某个音乐参数变了 → 耳朵听到的就变了」的那部分：

| 归到乐理课 | 归属理由 |
|---|---|
| **律动：节奏型怎么设计** | 密度 / 重音 / 音长三个旋钮一改，听感立刻不同。织体表就是"音头落在第几拍"，密度能算成每秒几个音头 |
| **曲式：12 小节布鲁斯** | 和弦进行是定数（全属七、第 9 小节必须 V7），AAB 是三个格子的长度关系，能数能听；同一段和声把八分音符后半从 ½ 挪到 ⅔，立刻从进行曲变成 shuffle |
| **配器：谁唱主、谁铺底** | 同一段旋律，换音区、换起音、让密度，就能从糊成一团变成层次分明——三件事全是可听的参数 |
| **专辑能量曲线** | 排序改的是相邻两首的调与密度差。同一批八首，换顺序听感完全不同，这是能听见的 |
| **跨曲动机（第 14 节 ④）** | 第 8 首让第 1 首重新响一次：轮廓不动、只改时值与配器，听众自己认出来——这条文字做不到 |
| **语言计时法** | 中文按字计时、英文按重音计时——同样是 8 拍，英文塞 11 个音节仍只落 4 个重音，这是节奏参数 |
| **粤语九声与入声** | 入声（-p/-t/-k）塞不进长音，是旋律时值的硬约束，和"倒字"同一条逻辑 |

其余留在作词课：押韵是音响选择但单位是韵母不是音高，属于词法层面；
hook、意象、八派这些是写作方法论，不对应任何音频参数。

**同一件事常常一半一半**。专辑规划就是典型：辙口怎么分布、题材怎么分配、标题怎么排
——那是文字的事，留在作词课第 12 节；同一张专辑的能量曲线与配器怎么排
——那是耳朵的事，进乐理课第 14 节。两页各答一半，合起来才是一张完整专辑，
所以乐理课那一节末尾有一条指向 `lyric.html#s-album` 的交叉引用。

**叙事专辑更极端：它必须两页合写。** 要说清"这一张在讲一个故事、八首各分担一段"，
得同时回答两件不同性质的事——八首各自承担哪个叙事阶段、同一套意象怎么复现并翻面
（作词课第 12 节的叙事功能表与意象系统），以及靠什么让听众觉出"合上了"
（乐理课第 14 节的动机变形 / 调性闭环 / 配器收放）。**前一半只能读，后一半只能听**，
拆开任一半都不成立。

## 版本号

**每次改动都要升版本号，四个入口共用一个号。**

唯一真源是各自的 `VERSION` 常量：`js/app.js`（乐理课）、`js/lyric-app.js`（作词课）、
`js/instrument-render.js`（乐器课）、`js/cards-app.js`（卡片版）。
`applyVersion()` 把它写进标签页标题、页面 H1、侧栏 brand 三处，
另有各页 HTML 里两处 `<span class="ver" data-ver>` 静态副本做首屏降级。

```bash
npm run version          # 自检：全部页面 × 四处一致 + 是否比上次提交高
npm run bump -- 1.25     # 一键升到 1.25（四页共 16 处，日期自动取当天）
```

`npm test` 之前会自动跑一次自检（`pretest`）。改了代码却没升版本会被拦住并提示该改成什么；
两页版本号不一致同样会被拦（这是最容易漏的一种——只升了一个页面的常量）。
确认是纯文档改动可显式跳过：`SKIP_VERSION_BUMP=1 npm test`。

**不要手改那十六处**——`npm run bump` 一次改齐并自带写后校验（改完立刻重读核对）。

## 测试

```bash
npm install     # 安装开发依赖 jsdom
npm test
```

两套测试：`tests/run-tests.js`（长网页版，81 项）与 `tests/cards-tests.js`（卡片版，17 项）。
其中 F 组是**声学验证**——把每张场景卡片真的渲染成 PCM 波形，
再做起始点检测 / Goertzel 音高跟踪 / 频谱质心 / 最小音程分析，
逐条核对"听起来的速度、调式、明暗、力度"是否与卡片描述相符。

卡片版这 17 项守的是它自己的骨架：装配与脚本顺序（含 `svg.js` 必须排在
`cards-widgets.js` 之前）、版本四处一致、每节一个章节头、文字块不丢不重、
互动卡 id 全都有实现、场景卡按维度分割、乐器 id 全在数据里、
进度存储往返与坏数据回落、切课回原页、互动卡的三个挂载位（上文 / 互动 / 图注）与
"两张互动卡叠一页"的排布、翻页按钮的汉字与点击区大小、顶栏总高不许变高、
**图文对账**（长网页每个"脚本产出容器"在卡片版都要有对应互动卡，而且真能画出 `<svg>`）、
**交互冒烟**（三课每张互动卡都真建一遍、点遍每个按钮/下拉/滑杆）、
以及几条 CSS 级硬约束（正文块不被 flex 压缩、卡片不滚动、横屏提示存在、量高留了余量）。
**"有没有被裁掉"不在其中**——见上一节。

覆盖范围：

- **A 资源与版本**：外链资源就位、favicon 三种声明与 ICO 尺寸档位、两页版本号八处一致、版面宽度对齐不变式、双页互链（顶部与目录各一条，目录那条必须排在章节链接之前且不被当成当前节点）与各自的页头插图
- **A9 织体总览表**：15 种织体一个不漏地列全（标题写几种就得有几行）；每一行的音头数 / 和弦周期 / 密度都必须现算而不是抄死值；长音织体的密度必须低于普通两拍织体的一半；律动选型表里用到的织体必须都在总览表里
- **B 页面装配**：17 节导航且节号 00–16 连续、两架键盘键数、各表格行数、SVG 方块数、91 张场景卡与 13 维筛选、律动网格 8 格 + 音头 + 音长尾、动机两条轮廓 8 个音、**每张表都必须套在 `.tscroll` 里且 wide 标记与列数一致**
- **C 乐理函数**：音名 / MIDI / 频率 / 三和弦 / 罗马数字 / 音名拼写；五声五调式的旋转关系守卫
- **D 歌词数据**：十三辙响度单调、四声镜像（倒字必须是把顺字翻过来）、气口字数自洽
- **E 交互冒烟**：桩 AudioContext 下点播各节按钮，验证出声 + 点亮链路无报错（含三档计时、两版粤语、布鲁斯、五种织体、三版编制、动机两版、动机生成五种手法、人声音区三档）
- **E14 人声舒适音区**：五个分区必须连续无缝不留缝；换声点必须落在中音区；**换声点名字里的音名要跟实际区间对得上**（防"文字说 E3、数据是 D♯4"）；三档演示的音程关系必须完全一致、只差八度高低
- **F 声学验证**：听感速度与描述同向（含"热血必须快过悬疑"回归）、音区/亮度/力度/空间/协和度与语义一致
- **F1b 密度口径**：密度公式的分母必须与排程真正用的和弦周期一致（反解 `ev.dur` 对账）；长音织体的周期必须大于 2 拍；周期一变公式必须跟着变慢；56 BPM 的铺底卡密度必须低于旧公式的一半
- **G 曲式与语言**：布鲁斯 12 格和弦守恒（第 9 小节必须 V7）、21 个词的音与逐格点亮、英文两行重音位置完全一致、九声里恰好三个入声且一律不可拖长
- **G5 律动**：五种织体真实存在、选型表全覆盖、音头必须从第 0 拍起、音头数恰好 1/2/4/4/4、密度 === 音头数 × BPM ÷（和弦周期拍数 × 60）；**哨兵**：拿长音织体（铺底，周期 6 拍）代进去验一遍公式，防止密度口径退回写死的 "/120"（五种律动织体的周期恰好都是 2 拍，写死旧公式照样全绿）；十六分网格画的是两拍，前提是这五种织体周期都是 2 拍，前提本身有断言守着
- **G5b 律动选型表**：表里"几个音头 / 几拍"两个数都必须现算（曾写死 "/ 2 拍"，而铺底真实周期是 6 拍）；文案里提到拍数的必须跟数据一致（"整小节一个音"与 6 拍周期脱节）
- **G6 配器**：每版编制恰好一位主乐、三层角色不重名、主乐音区必须高于铺底、主乐必须弹满 10 个音；专辑两种排法都是 0–7 的排列，且重排后的"相邻同调"次数必须少于原序
- **G6b 调式 id 与进行**：调式 id 必须取自 28 个合法值（`minor` 不是合法 id，自然小调是 `aeolian`；非法 id 会**静默回落大调**）；四处演示的 `k` 都得合法；GROOVE / ENSEMBLE 的进行必须是 `aeolian` 的 i–VI–III–VII（`[0,5,2,6]`），且 ENSEMBLE 的 10 个旋律音每个都得落在当下和弦音上
- **G7 跨曲动机**：两版**音高轮廓必须一个音都不改**、时值与起点必须整体一倍、回来版层数更多、最后一音正好晚一倍；三个把手每条都要写出"怎么动 / 听出什么 / 做错了"
- **G9 动机怎么生成**：只会变形还不够，得会造——五种手法（节奏化 / 移位 / 逆行 / 移调 / 增减音）各自守住它的定义：节奏化只改时值不改音高、逆行必须是倒序、移调必须等音程平移且**不能跑出调式**、增减音只差一个音；母动机必须是原有那条，界面上五个手法都得能切、图必须重画
- **L 作词课**：16 节装配且节号 00–15 连续、表格横滑守卫、体裁联动真的换方案/严格度/纪律、自检器双向（有问题的词必须报、干净的必须放过）、八派只有三种力且各三条动作
- **L6 术语与扩充表**：韵脚五型的英文词必须各带一句"为什么叫这个"（perfect=完全 / slant=斜是点名要的两条）、七种修辞只有句内/跨句两种层级且跨句恰两种、国风库六组每组恰八个词且 48 个词跨组不重复、段落九行与人称四种都要有英文名与判据、并核对这些表真的画到了 DOM 上
- **L5 叙事专辑**：八个阶段串行且功能只有起/承/转/合四种、每种恰好两首、位置不许跳号；三个意象每个都要有"第一次 / 后来 / 翻的是哪一格"，两次出现不许是同一句话
- **L7 古风两节**：三型必须恰好一型是默认（默认是乙）、古风能套的四派 + 两对硬冲突、四条硬纪律编号连续、八类意象、**文言浓度三重代价必须齐全（少「韵脚被埋」这条就红）**、六种句法骨架、五套公式句、七条四诊、物候四季 + 梅雨与雁南飞必须被点名
- **L8 古风自检器**：万能词两个阈值（种类 ≤3 且各只用一次）、五套公式句里能查的四套、物候互斥（guofeng 那个"梅雨 + 杏花 + 蝉声"的真实反例必须被抓到）、**韵脚被文言虚词占了几处**；文言虚词表不许收「者/夫/其/所/且」这类现代汉语仍在用的字（会大量误报）

## 卡片版（cards.html）

同一份内容，第二套版面：**一屏一张卡，不上下滚动、不左右滚动**。手机竖着拿听课用，
电脑上打开只是一条 620px 宽的中栏（左右留白，不做两栏）。

- **内容不重写**：`tools/build-cards-data.js` 用 jsdom 真跑三页脚本，再从渲染结果里抽文字层，
  产出 `js/cards-data.js`。所以长网页改了文案，重跑这个生成器即可同步——
  它必须"先跑完 JS 再抽"，否则乐器家族导语、各张速查表都只剩标题。
  反过来，"跑完 JS 就抽"也会抽到**控件自己的输出**：#progStrip / #cadStrip 里那几个
  和弦块的内层 `<div class="mini">` 曾被当成段落抓走，于是每节多出几张只印着
  「I」「V」「vi」「IV」的卡片。这类容器一律进 `DROP_SEL`。
- **分页靠实测**：`cards-app.js` 先量出正文可用高度，再把文字块按真实高度装袋。
  放不下的长段落按句末标点切段（`splitHtml`），表格按行分页，列表按条分页；
  小标题/章节头不许留在卡底，装得下就一起带到下一张；表格装完若还有空档，
  紧跟的段落会接着排进同一张。
- **单薄卡回收**（`rebalance`）：装完再回头收拾"一整页只有一两行字"的卡，按优先级——
  并进上一张 → 从上一张末尾借块垫厚 → 上一张是互动卡/表格借不动就塞进下一张开头。
  只剩标题的卡一律往后并（标题本来就该压着正文）；章节头不往前并。
  两条互动卡各自都不满半屏时叠成一页（中间一条虚线分隔），乐器课的 39 张音域图因此省掉二十来页。
- **互动卡**：`cards-widgets.js` 把长网页里的交互件重画成自带 DOM 的卡片，
  播放仍走 `playback.js` 的 `seq / scenePlay / playGroove …`（真源只有一套）。
  讲得少、留白多的卡，互动区会并入文字卡下半张（`.has-blocks`）；
  互动卡后面跟的一句结论会挂成它的图注（`after`，排在 `.w` 之下），不再单独占一页。
- **图要单独补，不能指望抽文字抽出来**（V1.45 的教训）：长网页有一半内容是
  `svg.js` 现画的示意图（阶梯图 / 和弦对比 / 十二格 / 语言时间轴 / 音区条 / 动机曲线…），
  以及 `buildProg` / 节拍器 / 《沧海一声笑》这类现搭的互动区。它们**不在 HTML 里**，
  第一版卡片只搬文字，于是这些图**整片消失**——文字还在，读者却看不到"看见"。
  现在 `cards.html` 与长网页共用同一份 `js/svg.js`，`cards-deck.js` 的 `PLAN` 是
  "长网页哪个容器 → 卡片版哪张卡"的账本，`K11` 拿 `index.html` 的容器 id 逐个对账：
  少一张、id 拼错、`svg.js` 没加载，都会红。
  图容器统一用 `figBox()` 建：它给每张图一个 id，`seq(steps, id)` 靠这个 id
  点亮图里的 `rect[data-note]`——不传 id 就只剩钢琴在闪，图是死的。
- **卡内纵向顺序由 CSS 的 `order` 定**，不靠 append 顺序：标题 0 → chips 1 →
  图 2（`.w-fig` / `.w-prog` / `.w-tl`）→ 播放按钮排 3（`.w-act`）→ 说明 9（`.w-read`）。
  否则"先建读出、最后补图"的写法会把图排到说明下面去。
- **顶栏**：中间是课名 + 页码（点开目录），两边是「上一页 / 下一页」——
  用汉字而不是 `‹ ›`，按 76×42 的可点区设计。顶栏总高锁在 82px 以内：
  按钮放大靠挤掉上下留白，不靠撑高顶栏（每长 1px，一屏就少一行字，`K10` 守着）。
- **常驻钢琴**只有乐理课显示，复用 `keyboard.js`；停止播放时清闪键并回正视口。
- **进度**按课存在 `localStorage`（键 `mt.cards.v1`，记页号 + 出处节 id），
  切走再切回接着上次；`#c=lyric&p=12` 可分享跳页，带深链进来不写存储。
- 手机横过来（矮于 520px）不排卡片，直接铺一句"请竖起来"——顶栏 + 钢琴会吃掉一多半高度。

**版面回归怎么验**：jsdom 不做布局，`npm test` 只能守结构与装订；
"有没有被裁掉"必须用真浏览器量。做法是给 `cards.html` 临时注入一段探测脚本，
用无头 Chrome 逐卡读 `scrollHeight - clientHeight`（正数=裁切）与
`scrollWidth - clientWidth`（正数=横向溢出），再逐张截图看排版。
Chrome 无头窗口最窄约 500px，量 390/360 这类手机宽度时要套一层 iframe
（`--allow-file-access-from-files`）。四个尺寸 × 三门课跑一遍应为 0 溢出。

**"这页是不是很空"不能用 `scrollHeight` 判**：它对没有溢出的元素永远返回 `clientHeight`，
内容只有一行也照样等于满屏，于是"稀卡"永远数是 0。要另算正文实际内容高——
把 `.dc-body` 每个子元素 `getBoundingClientRect().height` 加起来再加行间距。
可用高度也要**按课分别读**：乐理课底部有常驻钢琴，`availH` 比另外两课小一截，
拿错一份阈值就会把能并的卡当成并不过去。

## 技术要点

- **Web Audio API 实时合成**：每个音 = 3 个振荡器（基频 / 八度 / 十二度泛音）+ 低通包络，
  参数全部查 `TONES` 表（22 种音色 = 起音时间/泛音配比/滤波亮度）；无任何音频文件
- **听感速度 = 音头密度**：耳朵判断快慢靠"每秒多少个音头"，不是 BPM 数字。
  织体表 `TEX` 声明每个和弦周期内音头落在第几拍，密度 =
  `hits.length × BPM ÷（和弦周期拍数 × 60）`。
  分母里的**和弦周期必须与排程真正用的那个一致**，所以周期由 `texSpan()` 单一来源给出：
  普通织体是 2 拍，长音织体要长得多（铺底/长音 6 拍、空五度 7 拍、钟鸣 3 拍），
  因为一个音得拖满、还得留出空隙。早期公式写死"周期＝2 拍"，
  于是 91 张卡片里有 30 张自报的听感速度偏高 20%–250%（长音卡偏高 200%）。
  卡片同时显示标称 BPM 与实测密度，两者不一致时以密度为准
- **窄屏表格横滑**：`th` 是 `nowrap` 的，4–5 列表格在 390px 下超出容器，
  **最后一列会被直接裁掉**（500px 以上完全看不出来，所以极易漏）。
  装配时给每张表套一层 `.tscroll`，只有 4 列以上的"宽表"才给 `min-width`——
  两三列的表硬撑宽只会让整页到处都要横滑；另留一条细滚动条当"可以滑动"的提示
- **纯函数排程**：`sceneEvents(cfg)` 不碰音频只算事件表，`bluesEvents()` / `langTiming()` /
  `grooveEvents()` / `ensembleEvents()` / `motifEvents()` 同理。
  测试直接验证这些函数，让"方块说的话"和"耳朵听到的"可以逐项对账
- **同一段旋律，三种编制**：主乐 / 和声 / 铺底三层各有音区与音头位置，
  三版刻意做成"同音色 → 只换音色 → 换音区又让密度"的递进，让"糊"与"分明"可以 A/B 听
- **同一段动机，两种规模**：跨曲呼应用的是"轮廓不动、只改时值与配器"。
  G7 守着"音高序列必须完全一致"这一条——改了轮廓还叫呼应，是最常见的假呼应
- **调式 id 必须查表**：`M_OF(id)` 找不到就**静默回落 ionian**，不报错。
  所以 `k:'minor'`（自然小调的合法 id 是 `aeolian`）这类写法不会崩，只会悄悄发大调。
  "不报错但结果错"的地方只能靠断言守着——G6b 逐个查四处演示的 `k` 与和弦进行
- **文言浓度 = 韵脚的可用空间**：这条不是比喻，是能数的。
  韵脚只能落在**分句的末字**上，而文言虚词（之乎者也矣焉兮）最爱占的就是这个位置——
  **那个字押不了韵**。所以文言浓度一高，能押韵的位置就成比例变少。
  自检器因此把整首按标点切成"分句"，数出：几个分句里有几个末字被文言虚词占了，
  剩下的才是你真正能押韵的位置。虚词表刻意只收「之乎也矣焉兮哉耳尔」，
  **不收「者夫其所且」**——那些现代汉语仍在用，收进来就是误报源，
  误报一次，人就不信这个检查了
- **数字与文案要对着念**：数据层加了东西、文案没跟上，这类错测试查不出来
  （"12 音"写成 13 行、标题说几种表里只有几种、手法标题与例句不符）。
  固定打法是按**数据层 → 文案 → 交叉引用 → 音频实现**四条各查各的，
  每条查出的错类型不一样
- **键盘音域 C3–D7**：可视窗固定两八度（C4–B5），超出部分左右溢出；
  播放时发声键自动贴边缘进入视口，键灭后 0.5s 滑回；支持鼠标/触屏拖动平移
- **版面宽度三层推导**：`--read`(790) → `--card-out`(834) → `--wrap-out`(898)。
  正文与卡片内文字都落在同一条内容框内，只有卡片边框向外突出
- **注释密度**：所有 js/css 文件按"文件头 → 分区横幅 → 函数级注释"三级写满，
  含历史踩坑记录（如键盘音域必须实测、pointer capture 会吞 click、
  只对齐宽度不缩进左缘则右边缘照样错开等）

## 部署

线上地址（Cloudflare Workers 静态资产）：

- **https://musictheory.2025120.xyz** —— 乐理课
- **https://musictheory.2025120.xyz/lyric.html** —— 作词课

纯静态站，无构建步骤，两个 HTML 都是入口。Cloudflare Workers 通过 Git 集成
（`github.com/Tairraos/musictheory`）自动构建部署：push `master` 后
Cloudflare 跑 `npm run build` 产出 `dist/`，再由 `npx wrangler deploy` 发布。

```bash
# 手动触发一次部署
npm run build && npx wrangler deploy
```

> 注：git remote 使用 SSH 地址（`git@github.com:Tairraos/musictheory.git`），
> 因为部分网络环境下 HTTPS 推送到 github.com 会被代理拦截。
> `npm test` 的 pretest 会先校验版本号，改了代码记得先 `npm run bump`。
>
> Workers 静态资产开了 pretty URL：`/lyric.html` 会 307 跳到 `/lyric`，
> 两个地址都能用，站内互相跳转不受影响。

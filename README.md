# 姐弟厨师团 —— 乐理课 · 作词课

两个可以"动手弄响"的互动课页面，共用一套零依赖的静态站。

| 页面 | 地址 | 讲什么 |
|---|---|---|
| **乐理课** | `index.html` | 半音 → 大小调 → 七个调式 → 五声偏音 → 和弦 → 终止式 → 速度 → 拍号 → 律动（节奏型） → 曲式（布鲁斯） → 词曲咬合 → 移调 → 十二种表达维度 → 配器与专辑 → 转调 → 速查 |
| **作词课** | `lyric.html` | 判据 → 体裁 → 押韵 → 中文句式 → 英文 prosody → 意象 → 钩子 → 八派 → 框景 → 禁则 → 改词 → 专辑规划 → 自检器 |

不啃符号、不背公式：乐理课每一块都能点、能听、能改参数；
作词课每条判据都标了"能不能数"——能数的交给自检器，只能人读的交给朗读。

两页在页面最顶上各有一条互链（`.pageswitch` 小药丸），从任意一页都能一步跳到另一页。

> 线上试玩：**https://musictheory.2025120.xyz**
> （`/` → 乐理课，`/lyric.html` → 作词课）

## 运行

工程是**零运行时依赖**的静态站，无构建、无网络请求
（声音全部由浏览器实时合成，插图与图标都是本地 PNG）。

直接双击 `index.html` 用浏览器打开即可；或起个本地服务：

```bash
npm start            # 等价于 python3 -m http.server 8000
# 打开 http://localhost:8000        → 乐理课
# 打开 http://localhost:8000/lyric.html → 作词课
```

建议用桌面端 Chrome / Edge / Safari，手机竖屏同样适配（乐理课底部有常驻钢琴）。

## 分界：什么算乐理，什么算作词

最初那批作词资料里只有约三成是真乐理——能写成「某个音乐参数变了 → 耳朵听到的就变了」的那部分：

| 归到乐理课 | 归属理由 |
|---|---|
| **律动：节奏型怎么设计** | 密度 / 重音 / 音长三个旋钮一改，听感立刻不同。织体表就是"音头落在第几拍"，密度能算成每秒几个音头 |
| **曲式：12 小节布鲁斯** | 和弦进行是定数（全属七、第 9 小节必须 V7），AAB 是三个格子的长度关系，能数能听 |
| **配器：谁唱主、谁铺底** | 同一段旋律，换音区、换起音、让密度，就能从糊成一团变成层次分明——三件事全是可听的参数 |
| **专辑能量曲线** | 排序改的是相邻两首的调与密度差。同一批八首，换顺序听感完全不同，这是能听见的 |
| **跨曲动机（第 14 节 ④）** | 第 8 首让第 1 首重新响一次：轮廓不动、只改时值与配器，听众自己认出来——这条文字做不到 |
| **语言计时法** | 中文按字计时、英文按重音计时——同样是 8 拍，英文塞 11 个音节仍只落 4 个重音，这是节奏参数 |
| **粤语九声与入声** | 入声（-p/-t/-k）塞不进长音，是旋律时值的硬约束，和"倒字"同一条逻辑 |

其余留在作词课：押韵是音响选择但单位是韵母不是音高，属于词法层面；
hook、意象、八派这些是写作方法论，不对应任何音频参数。

**同一件事常常一半一半**。专辑规划就是典型：辙口怎么分布、题材怎么分配、标题怎么排
——那是文字的事，留在作词课第 11 节；同一张专辑的能量曲线与配器怎么排
——那是耳朵的事，进乐理课第 14 节。两页各答一半，合起来才是一张完整专辑，
所以乐理课那一节末尾有一条指向 `lyric.html#s-album` 的交叉引用。

**叙事专辑更极端：它必须两页合写。** 要说清"这一张在讲一个故事、八首各分担一段"，
得同时回答两件不同性质的事——八首各自承担哪个叙事阶段、同一套意象怎么复现并翻面
（作词课第 11 节的叙事功能表与意象系统），以及靠什么让听众觉出"合上了"
（乐理课第 14 节的动机变形 / 调性闭环 / 配器收放）。**前一半只能读，后一半只能听**，
拆开任一半都不成立。

## 版本号

**每次改动都要升版本号，两个页面共用一个号。**

唯一真源是各自的 `VERSION` 常量：`js/app.js`（乐理课）、`js/lyric-app.js`（作词课）。
`applyVersion()` 把它写进标签页标题、页面 H1、侧栏 brand 三处，
另有 `index.html` / `lyric.html` 里各两处 `<span class="ver" data-ver>` 静态副本做首屏降级。

```bash
npm run version          # 自检：全部页面 × 四处一致 + 是否比上次提交高
npm run bump -- 1.25     # 一键升到 1.25（两页共 8 处，日期自动取当天）
```

`npm test` 之前会自动跑一次自检（`pretest`）。改了代码却没升版本会被拦住并提示该改成什么；
两页版本号不一致同样会被拦（这是最容易漏的一种——只升了一个页面的常量）。
确认是纯文档改动可显式跳过：`SKIP_VERSION_BUMP=1 npm test`。

**不要手改那八处**——`npm run bump` 一次改齐并自带写后校验（改完立刻重读核对）。

│   ├── keyboard.js          # 钢琴键盘组件：绘制、亮键、闪灯、视口管理

│   ├── sections.js          # 乐理课装配层：逐节生成 chips/表格/场景卡并绑定播放
│   ├── lyric-render.js      # 作词课装配层：铺表 + 体裁联动 + 自检器
│   ├── app.js               # 乐理课入口：VERSION + 全局状态 + init

│   └── images/
│       ├── hero-art.png     # 乐理课页头插图（透明底 PNG，标题画在图里）

**双击 HTML 也能离线跑**，不需要服务器。作词课刻意不加载 `data.js` / `utils.js`：
`utils.js` 依赖 `data.js` 里的常量，带上会把整个乐理数据层拖进一个不需要音频的页面。

## 测试

```bash
npm install     # 安装开发依赖 jsdom
npm test
```

55 项检查。其中 F 组是**声学验证**——把每张场景卡片真的渲染成 PCM 波形，
再做起始点检测 / Goertzel 音高跟踪 / 频谱质心 / 最小音程分析，
逐条核对"听起来的速度、调式、明暗、力度"是否与卡片描述相符。

覆盖范围：

- **A 资源与版本**：外链资源就位、favicon 三种声明与 ICO 尺寸档位、两页版本号八处一致、版面宽度对齐不变式、双页互链与各自的页头插图
- **B 页面装配**：17 节导航且节号 00–16 连续、两架键盘键数、各表格行数、SVG 方块数、91 张场景卡与 13 维筛选、律动网格 8 格 + 音头 + 音长尾、动机两条轮廓 8 个音
- **C 乐理函数**：音名 / MIDI / 频率 / 三和弦 / 罗马数字 / 音名拼写；五声五调式的旋转关系守卫
- **D 歌词数据**：十三辙响度单调、四声镜像（倒字必须是把顺字翻过来）、气口字数自洽
- **E 交互冒烟**：桩 AudioContext 下点播各节按钮，验证出声 + 点亮链路无报错（含三档计时、两版粤语、布鲁斯、五种织体、三版编制、动机两版）
- **F 声学验证**：听感速度与描述同向（含"热血必须快过悬疑"回归）、音区/亮度/力度/空间/协和度与语义一致
- **G 曲式与语言**：布鲁斯 12 格和弦守恒（第 9 小节必须 V7）、21 个词的音与逐格点亮、英文两行重音位置完全一致、九声里恰好三个入声且一律不可拖长
- **G5 律动**：五种织体真实存在、选型表全覆盖、音头必须从第 0 拍起、音头数恰好 1/2/4/4/4、密度 === 音头数 × BPM ÷ 120
- **G6 配器**：每版编制恰好一位主乐、三层角色不重名、主乐音区必须高于铺底、主乐必须弹满 10 个音；专辑两种排法都是 0–7 的排列，且重排后的"相邻同调"次数必须少于原序
- **G7 跨曲动机**：两版**音高轮廓必须一个音都不改**、时值与起点必须整体一倍、回来版层数更多、最后一音正好晚一倍；三个把手每条都要写出"怎么动 / 听出什么 / 做错了"
- **L 作词课**：13 节装配、体裁联动真的换方案/严格度/纪律、自检器双向（有问题的词必须报、干净的必须放过）、八派只有三种力且各三条动作
- **L5 叙事专辑**：八个阶段串行且功能只有起/承/转/合四种、每种恰好两首、位置不许跳号；三个意象每个都要有"第一次 / 后来 / 翻的是哪一格"，两次出现不许是同一句话

## 技术要点

- **Web Audio API 实时合成**：每个音 = 3 个振荡器（基频 / 八度 / 十二度泛音）+ 低通包络，
  参数全部查 `TONES` 表（22 种音色 = 起音时间/泛音配比/滤波亮度）；无任何音频文件
- **听感速度 = 音头密度**：耳朵判断快慢靠"每秒多少个音头"，不是 BPM 数字。
  织体表 `TEX` 声明每个和弦周期内音头落在第几拍，密度 = `hits.length × BPM ÷ 120`。
  卡片同时显示标称 BPM 与实测密度，两者不一致时以密度为准
- **纯函数排程**：`sceneEvents(cfg)` 不碰音频只算事件表，`bluesEvents()` / `langTiming()` /
  `grooveEvents()` / `ensembleEvents()` / `motifEvents()` 同理。
  测试直接验证这些函数，让"方块说的话"和"耳朵听到的"可以逐项对账
- **同一段旋律，三种编制**：主乐 / 和声 / 铺底三层各有音区与音头位置，
  三版刻意做成"同音色 → 只换音色 → 换音区又让密度"的递进，让"糊"与"分明"可以 A/B 听
- **同一段动机，两种规模**：跨曲呼应用的是"轮廓不动、只改时值与配器"。
  G7 守着"音高序列必须完全一致"这一条——改了轮廓还叫呼应，是最常见的假呼应
- **键盘音域 C3–D7**：可视窗固定两八度（C4–B5），超出部分左右溢出；
  播放时发声键自动贴边缘进入视口，键灭后 0.5s 滑回；支持鼠标/触屏拖动平移
- **版面宽度三层推导**：`--read`(790) → `--card-out`(834) → `--wrap-out`(898)。
  正文与卡片内文字都落在同一条内容框内，只有卡片边框向外突出
- **注释密度**：所有 js/css 文件按"文件头 → 分区横幅 → 函数级注释"三级写满，
  含历史踩坑记录（如键盘音域必须实测、pointer capture 会吞 click、
  只对齐宽度不缩进左缘则右边缘照样错开等）

## 部署

线上地址（Cloudflare Workers 静态资产）：

- **https://musictheory.2025120.xyz** —— 乐理课
- **https://musictheory.2025120.xyz/lyric.html** —— 作词课

纯静态站，无构建步骤，两个 HTML 都是入口。Cloudflare Workers 通过 Git 集成
（`github.com/Tairraos/musictheory`）自动构建部署：push `master` 后
Cloudflare 跑 `npm run build` 产出 `dist/`，再由 `npx wrangler deploy` 发布。

```bash
# 手动触发一次部署
npm run build && npx wrangler deploy
```

> 注：git remote 使用 SSH 地址（`git@github.com:Tairraos/musictheory.git`），
> 因为部分网络环境下 HTTPS 推送到 github.com 会被代理拦截。
> `npm test` 的 pretest 会先校验版本号，改了代码记得先 `npm run bump`。
>
> Workers 静态资产开了 pretty URL：`/lyric.html` 会 307 跳到 `/lyric`，
> 两个地址都能用，站内互相跳转不受影响。
